# Migration Guide for v0.4

Migrating from `0.3` (`v0.3`) to the latest `0.4.x` (`v0.4.7`).

## Required changes

- **`confluent-kafka-helpers` is now required** (install it; `0.4.7` still pulls it via `dependency_links`).
- **Identity is `id`**: `guid` / `aggregate_guid_attr` / `create_guid` → `id` / `create_id` (`0.4.7`).
- **Event-sourced commands moved**: `CommandHandler` no longer loads or saves the aggregate. Use `ESCommandHandler` for that; keep `CommandHandler` for non-ES handlers.
- **Repository API**: `save` → `commit`; default backend key `kafka` → `kafka_avro`; pass `config` with `backend_config` (not a flat dict). `KafkaBackend` → `KafkaAvroBackend`.
- **Entity methods**: `apply` → `apply_event`; `clear_commited_events` → `clear_staged_events`.
- **Handlers take `message_deserializer` in `__init__`** (class-level `handlers` dict). A `Handler` base class is shared by command and event handlers.
- **`Message` helper** (`0.4.x`): namedtuple messages go through `eventsourcing_helpers.message.Message` / `message_factory`.

### Migration steps

1. Add the Kafka helpers dependency and switch event-sourced handlers:

   ```python
   # Before (0.3)
   class MyHandler(CommandHandler):
       aggregate_root = Order
       aggregate_guid_attr = "guid"
       # handle() loaded the aggregate and called repository.save

   # After (0.4)
   class MyHandler(ESCommandHandler):
       aggregate_root = Order
       repository_config = {...}  # must include backend_config
   ```

2. Replace `repository.save(aggregate)` with `repository.commit(aggregate)` and `guid` with `id`.
3. Rename `apply(...)` → `apply_event(...)` and `clear_commited_events()` → `clear_staged_events()`.

## Optional changes

- **`MessageBus` / `Consumer`**: produce/consume without going through the repository — use when you need a standalone bus (`kafka_avro` backend).
- **Non-ES `CommandHandler`**: handle commands that do not load an aggregate.
