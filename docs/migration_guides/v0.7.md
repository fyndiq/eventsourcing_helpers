# Migration Guide for v0.7

Migrating from `0.6` (`v0.6.3`) to the latest `0.7.x` (`v0.7.9`).

## Required changes

- **`Repository` constructor and `load`**: `__init__` requires `aggregate_root_cls`. `load(id)` returns an `AggregateRoot` (snapshot or event replay) — it is no longer a context manager that yields raw events (`0.7.3`).
- **`jsonpickle` is required** from `0.7.3`/`0.7.9` (snapshots). `confluent-kafka-helpers` pin moves to `==0.6.1` (`0.7.1`+).
- **Offset watchdog** (`0.7.0`): Kafka consume can skip already-seen messages; configure `offset_watchdog` in the bus config (null backend is the default).

### Migration steps

1. Pass the aggregate class into `Repository` and treat `load` as returning the aggregate:

   ```python
   # Before (0.6)
   repo = Repository(config)
   with repo.load(id) as events:
       ...

   # After (0.7)
   repo = Repository(config, aggregate_root_cls=Order)
   order = repo.load(id)
   ```

2. Install `jsonpickle` and `confluent-kafka-helpers==0.6.1`.
3. If you need duplicate-consume protection, add offset-watchdog config (Redis extra: `pip install eventsourcing-helpers[redis]`).

## Optional changes

- **Snapshots** (`0.7.3`): persist aggregate state (null backend by default; Mongo via `pip install eventsourcing-helpers[mongo]`).
- **Handler metrics tags**: handle timings include message type/class — no code change unless you query those metrics.
