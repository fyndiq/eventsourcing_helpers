# Migration Guide for v0.3

Migrating from `0.2` (`v0.2`) to the latest `0.3.x` (`v0.3`).

## Required changes

- **Handler modules split**: `eventsourcing_helpers.handler` is removed. Import `CommandHandler` from `command_handler` and `EventHandler` from `event_handler`.
- **Class renames**: `BaseCommandHandler` → `CommandHandler`, `BaseEventHandler` → `EventHandler`, `BaseAggregate` → `Entity` (subclass `AggregateRoot` for the root).
- **CommandHandler attributes**: `aggregate` → `aggregate_root`, `aggregate_id_attr` → `aggregate_guid_attr`.
- **Entity identity**: use public `guid` (not `_guid`). `mark_events_as_commited` → `clear_commited_events`.
- **Serializers moved**: `from_message_to_dto` / `to_message_from_dto` live in `eventsourcing_helpers.serializers` (not `message`).

### Migration steps

1. Update imports and base classes:

   ```python
   # Before (0.2)
   from eventsourcing_helpers.handler import BaseCommandHandler, BaseEventHandler
   from eventsourcing_helpers.message import from_message_to_dto
   from eventsourcing_helpers.models import BaseAggregate

   # After (0.3)
   from eventsourcing_helpers.command_handler import CommandHandler
   from eventsourcing_helpers.event_handler import EventHandler
   from eventsourcing_helpers.serializers import from_message_to_dto
   from eventsourcing_helpers.models import AggregateRoot
   ```

2. On command handlers, rename `aggregate` → `aggregate_root` and `aggregate_id_attr` → `aggregate_guid_attr`.
3. On aggregates, subclass `AggregateRoot`, read/write `guid`, and call `clear_commited_events()` instead of `mark_events_as_commited()`.
