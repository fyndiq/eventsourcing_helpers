# Migration Guide for v1

Migrating from `0.8` (`v0.8.13`) to the latest `1.x` (`1.4.2`). There are no `v1.*` git tags; versions are taken from `setup.py`.

## Required changes

- **`confluent-kafka-helpers` 1.x** (`1.0.0`): require `confluent-kafka-helpers>=1.0.0` (`==1.0.0.dev0` at the `1.0.0` bump, then relaxed). This is the Kafka/OTel stack this line is built on.
- **`pydantic>=2` becomes a hard dependency** (`1.1.0`) even if you do not use `PydanticMixin`.
- **Mock `Consumer.add_message` signature** (`1.4.2`): `add_message(message_class=..., data=...)` → `add_message(key=..., value=...)`. The `mock` backend class path is `...mock.backend.MockBackend` (no longer `...mock.MockBackend`).
- **Mock producer records the serialized envelope** (first released in `1.2.0`): `MockBackend.produce` serializes a `Message` / `PydanticMixin` DTO before recording it, so the producer holds `{"key": ..., "value": {"class": ..., "data": {...}}}` instead of the DTO. Assertions that pass a DTO as `value` now compare a `Message` against a `dict` and fail with `AttributeError: 'dict' object has no attribute '__dict__'`. Build the expected message as an envelope dict instead.

### Migration steps

1. Upgrade `confluent-kafka-helpers` to 1.x and install `pydantic>=2`.
2. Update mock consumers that seed messages:

   ```python
   # Before (0.8 / 1.0–1.4.1)
   messagebus.consumer.add_message(
       message_class="UpdateArticleStock", data={"id": "<article-id>"}
   )

   # After (1.4.2)
   messagebus.consumer.add_message(
       key="<article-id>",
       value={"class": "UpdateArticleStock", "data": {"id": "<article-id>"}},
   )
   ```

3. Build every expected message as an **envelope dict**, in a helper next to the test. Do not construct a DTO and do not serialize one — tests describe the message on the wire:

   ```python
   # tests/integration/events.py
   def build_article_review_updated_event(article_id, **data):
       return {
           "key": article_id,
           "value": {
               "class": "ArticleReviewUpdated",
               "data": {"id": article_id, "action": "CREATED", "stars": 5} | data,
           },
       }
   ```

   ```python
   # Before (0.8) — compares against a DTO
   expected_event = events.ArticleReviewUpdated(id=article_id, action="CREATED", stars=5)
   messagebus.producer.assert_one_message_produced_with(key=article_id, value=expected_event)

   # After — compares against the envelope the producer actually recorded
   messagebus.producer.assert_message_produced_with(
       **build_article_review_updated_event(article_id)
   )
   ```

   Add `topic` / `headers` to the dict when the test asserts them; the producer records whatever keyword arguments `produce` was called with.

   This applies to **every** comparison against a produced message, including raw ones that never call a helper:

   ```python
   assert messagebus.producer.messages[-1] == build_article_review_updated_event(article_id)
   ```

   Grep for `value=` next to `producer.` — a suite that stops at the first failure will hide the rest.

4. Pick the assertion helper by what the test means. `assert_messages_produced_with` is the non-deprecated one, but it is **not a drop-in replacement**: it compares the whole produced list in order, whereas `assert_message_produced_with` asserts membership. Swapping it into a loop over expected events changes what the test asserts.

   ```python
   messagebus.producer.assert_messages_produced_with(
       [build_article_created_event(article_id), build_article_paused_event(article_id)]
   )
   ```

5. If you set the backend as a full class path, point it at `eventsourcing_helpers.messagebus.backends.mock.backend.MockBackend` (the `mock` alias still works).

### Target shape

`article-handler-service` (`tests/integration/command_handler/`) is the reference layout. A migrated suite looks like this:

- Override the plugin's `consumer` fixture to return the application's consumer; `messagebus` and `consume_messages` then come from the `pytest11` entry point — no local mock wiring.
- Build commands and events as **envelope dicts** in `commands.py` / `events.py` helpers (step 3). No DTOs anywhere in the test path, and no serializer imports.
- Drive a test with `consume_messages([build_x_command(...), ...])`, then assert the full output with `messagebus.producer.assert_messages_produced_with([build_x_event(...), ...])`.
- Clear state between tests with an autouse fixture calling `messagebus.producer.clear_messages()`.

## Optional changes

- **OpenTelemetry spans** (`1.0.0`): command/event handlers emit OTel spans via `eventsourcing_helpers.tracing` — no call-site change unless you customize the tracer.
- **`PydanticMixin`** (`1.1.0`): frozen Pydantic v2 models with `to_dict()` / `_class` — use when commands/events should be Pydantic models. Import from `eventsourcing_helpers.message` on this line.
- **Pytest plugin** (`1.1.0`): fixtures `consumer`, `messagebus`, `consume_messages` via the `pytest11` entry point. See **Target shape** above for how a migrated suite uses them.
- **`assert_num_messages_produced`** (`1.3.0`) and **`assert_messages_produced_with_class_names`** (`1.4.0`): extra mock producer assertions, for when you only care about the count or the class names.
- **`assert_message_produced_with(..., topic=...)`** (`1.4.2`): pass `topic` when you need to assert the produced topic.
