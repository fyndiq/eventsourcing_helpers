# Migration Guide for v0.6

Migrating from `0.5` (`v0.5.2`) to the latest `0.6.x` (`v0.6.3`).

## Required changes

- **`confluent-kafka-helpers` pin moves to 0.5.x** (`==0.5.0` at `0.6.0`, `==0.5.2` at `0.6.3`).
- **`message_factory` signature** (`0.6.3`): `message_factory(message)` → `message_factory(message_cls, is_new=True)`. `MessageProxy` is replaced by `NewMessage` / `OldMessage`.
- **Missing apply methods raise** (`0.6.3`): `Entity.apply_event` raises `MissingEntityApplyMethod` instead of only logging.

### Migration steps

1. Upgrade `confluent-kafka-helpers` to the 0.5.x pin for this line.
2. Update `message_factory` call sites:

   ```python
   # Before (0.5)
   proxy = message_factory(MyTuple)

   # After (0.6)
   proxy = message_factory(MyTuple, is_new=True)
   ```

3. Catch `MissingEntityApplyMethod` (or add the missing `apply_*` method) if you previously relied on a log-and-continue missing apply.

## Optional changes

- **Datadog metrics** (`0.6.0`): `eventsourcing_helpers.metrics` (`call_counter`, `timed`, `StatsdNullClient`) — use when you want handler/repository timings without a StatsD agent.
