# Migration Guide for v2

Migrating from `1.x` (`1.4.2`) to the latest `2.x` (`2.3.0`). Only `v2.1.0` is tagged; `2.0.0`–`2.3.0` are `setup.py` bumps.

## Required changes

- **`PydanticMixin` import**: the module was split. `eventsourcing_helpers.message.PydanticMixin` → `eventsourcing_helpers.message.pydantic.PydanticMixin`.
- **`pydantic` is an extra**: it is no longer a hard dependency. If you use `PydanticMixin`, `pip install eventsourcing-helpers[pydantic]` (`pydantic>=2`).
- **Old mock `add_message(message_class=..., data=...)` API**: the default `mock` backend keeps the `1.4.2` `key`/`value` API. To keep the pre-1.4.2 seed style, use `mock_compat` / `backend_compat.MockBackend`.

### Migration steps

1. If you use Pydantic messages, install the extra and change the import:

   ```python
   # Before (1.x)
   from eventsourcing_helpers.message import PydanticMixin

   # After (2.x)
   from eventsourcing_helpers.message.pydantic import PydanticMixin
   ```

2. If tests still seed the bus with `message_class`/`data`, point the backend at the compat class:

   ```python
   # Before (old mock)
   # eventsourcing_helpers.messagebus.backends.mock.MockBackend
   messagebus.consumer.add_message(
       message_class="UpdateArticleStock", data={"id": "<article-id>"}
   )

   # After (2.x) — keep that call style
   # eventsourcing_helpers.messagebus.backends.mock.backend_compat.MockBackend
   # or MessageBus backend alias "mock_compat"
   ```

   If you already migrated tests to `add_message(key=..., value=...)` on `1.4.2`, keep the default `mock` backend.

## Optional changes

- **`PydanticMixin` extra fields** (`2.1.0`): `extra` is `"ignore"` (was `"forbid"`) so unknown payload fields no longer fail validation.
- **Custom DTO deserializers** (`2.2.0`): register an event **class** (not only a class-name string) in `EventHandler.handlers` to deserialize into that type via `from_message_to_dto(..., deserialize_class=...)`.
- **Mock dict headers** (`2.2.1`): `create_message` / `add_message` accept a headers **dict** as well as a list of pairs.
- **Mock `stop_on_eof`** (`2.3.0`): set `config["consumer"]["stop_on_eof"]` (default `True`) to keep the mock consume loop running when the queue is empty.
