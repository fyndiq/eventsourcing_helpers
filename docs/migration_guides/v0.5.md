# Migration Guide for v0.5

Migrating from `0.4` (`v0.4.7`) to the latest `0.5.x` (`v0.5.2`).

## Required changes

- **`cnamedtuple` is a hard dependency** — install `cnamedtuple>=0.1.6`.
- **`confluent-kafka-helpers` is pinned** (`==0.4.0` at `0.5.0`, `==0.4.3` at `0.5.2`). That helper's loader is a context manager, so `Repository.load` must be used as `with repo.load(id) as events:` if you call it yourself (the library's `ESCommandHandler` already does).
- **DTO metadata key**: `meta_data` → `meta` on deserialized messages.
- **Entity methods made private**: `clear_staged_events` → `_clear_staged_events`, `apply_events` → `_apply_events`. Call `apply_event` / `create_id` as before.

### Migration steps

1. Install `cnamedtuple` and the pinned `confluent-kafka-helpers` version for this line.
2. If you call `Repository.load` yourself, use it as a context manager:

   ```python
   # Before (0.4)
   events = repository.load(id)

   # After (0.5)
   with repository.load(id) as events:
       ...
   ```

3. Read `message.meta` (not `meta_data`) on DTOs. Stop calling `clear_staged_events` / `apply_events` from consumer code.

## Optional changes

- **`ESEntityBuilder`** (`0.5.2`): rebuild an entity from the store up to an optional `max_offset`.
